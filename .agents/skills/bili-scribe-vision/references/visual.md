# 视频关键帧与操作状态

视频图像理解须由用户选择。当前 Codex 消费“转录文字 + 图像”，脚本只做本地采样和选帧。

## 自动检测

video_visual.py --video 使用低分辨率变化检测，提议视觉状态；自动类型默认 OTHER，由执行者核对为 SLIDE、WHITEBOARD、PDF_VIEW、CODE 或 SOFTWARE_DEMO。大画面变化提议新状态，小鼠标运动通常忽略；长静态区间按时长上限划分。

对每个状态选稳定完成态，排除明显空白/过渡/遮挡；adaptive 在边缘内容量明显减少时保留一张擦除前画面。画面变稳定不等于老师已讲完；边缘数量只是本地启发式，不能证明语义完整。

候选在本地处理；送当前 Codex 的只有选中关键帧。默认每状态 1–2 张。

## 操作课程的关键区别

“每状态 1–2 张”不是“整段演示最多两张”。一次演示可能需要多个状态：

入口 → 菜单/参数窗口 → 输入完毕 → 执行 → 结果/验证。

自动检测可能漏掉短暂下拉框、同页参数修改、小面积输出。读转录后，当前 Codex 应核对关键动作的画面覆盖；缺失时用 --windows-json 定向补充，必要时提高局部采样频率。不要提高全课程的模型图片数量来替代对具体缺失步骤的定位。

windows JSON 示例：

{"segments": [
  {"start": 0, "end": 12, "type": "SOFTWARE_DEMO"},
  {"start": 12, "end": 18, "type": "SOFTWARE_DEMO"},
  {"start": 18, "end": 30, "type": "SOFTWARE_DEMO"}
]}

时间窗需有序、不重叠，整讲正式准备时连续覆盖。可以先对局部窗口选帧核查，然后合并成整讲连续窗口重跑。选帧会重新生成 ID，因此相关理解记录需重新核对输入指纹。

## 复现目标

关键帧须支持讲义中的位置、选项、参数、命令、图形和结果。模型要实际打开图片，结合对应文字判断操作。单独保留结果页面不能证明前面的步骤。

ROI 参数可排除画中画摄像头对检测的影响；保存的原图仍为完整画面。Unicode Windows 路径支持图片写入。原图保存在本地缓存，正式学习资料默认引用时间与证据条目，不作为源代码分发。
