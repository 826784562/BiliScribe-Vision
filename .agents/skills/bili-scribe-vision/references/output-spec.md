# 最终学习资料与操作复现标准

视频理解完成后由当前 Codex 结合材料撰写，课程和教材保持来源边界。输出：
course_manifest.json、understanding_manifest.json、大纲.md、讲义/、术语表.md、习题讲解.md、交付报告.md；有课本时再加 textbook_manifest.json 和互补大纲.md。

## 逐讲讲义

首行必须包含该讲 lesson_id，例如 # L001 · 软件操作。按课程组织概念、符号/公式与条件、实际推导、例题、易错点、重点、略过事件。不用空标题伪装完成。

视频内容引用已完成理解条目，例如：
- 老师口述支持的陈述（L001 00:00:05；L001-VS0001-E1）。
- [视频画面] 参数窗口中显示具体选项（L001 00:00:08；L001-VS0001-E2）。
课件引用文件和页/幻灯片；正文中的每个课本补充都带 C001 等章节 ID、课本 P12 与 PDF 第 16 页，并能对应已确认映射和选中范围。

口述、视觉和教材矛盾并列说明，不擅自统一。没讲过的推导只放明确 AI 补解/说明区。

## 操作类讲义：只看文档也能做

操作类课程不能只写“老师进行了某操作”。每项操作整理为：

- 操作目标和结束时应达到的结果。
- 环境与前置状态：软件/版本信息、窗口、文件、已有对象、必要配置；视频未交代的注明未知。
- 按顺序列步骤表：位置/入口、动作、输入值或命令、预期结果、核对方法、来源。
- 控件定位具体到菜单层级、面板、按钮文字或相对位置；避免“点这里”“按上面设置”。
- 参数包含数值、单位、范围和选项，代码/命令保留足以执行的完整文本。不要从常识补造未展示的默认设置。
- 记录结果形状、关键数值、输出文件位置或可见成功状态；缺证据时写待核对。
- 有证据的失败表现与恢复步骤；推测排错方法必须标 AI 说明。
- 必要时分多个操作状态补读中间界面。输出可附本地关键画面引用，但文字仍要能定位操作。

做“屏幕不可见”走查：仅从讲义的初始状态顺次执行，逐步检查能否知道位置、输入、结果和成功标准。没有关键步骤证据时列待补清单，不能声称完整可复现。文档走查通过与软件实际执行通过分别记录；无授权/环境时不强行实机操作。

理论课程也应让读者无需回看画面就知道符号含义、图形关系、条件和实际推导步骤。

## 资料融合

视频理解是主轴。PPT 补定义/符号，课本补选中章节的解释/推导；匹配依据不清楚就列未匹配材料，不把所有教材直接堆入讲义。章节顺序不覆盖学习顺序，资料内容不变成老师口述。

## 独立习题

习题讲解.md 中区分课程完整解、课程部分解、课程仅答案；题干、老师步骤、答案、易错提醒带来源。AI 补解单独分区。操作演示可在逐讲讲义内形成步骤，课程习题仍独立成册。

## 交付报告

必须写实际 mode（transcript-images/transcript-only）和“未直接听取原始音频”；记录已理解/未完成讲次与状态、图像读取方式、操作关键步骤覆盖、缺失、资料选择/页码、冲突、延期、语义抽查和实机验证状态。

validate_course.py 只验证结构和记录关系，不能证明内容正确、图片确实看过或操作已在用户环境成功。语义抽查需当前 Codex 回到对应转录、关键帧/材料对照，报告真实样本与发现。
